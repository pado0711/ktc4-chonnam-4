# 지원 판정 이력과 연속 달성 정책

브랜치 `feat/roleplay-support-adjustment`의 기준은 develop `ccfdff0`이다. 입력 복구 브랜치에 의존하지 않으며 프론트엔드는 수정하지 않는다.

## 확정 정책

사용자 확정에 따라 서로 다른 작은 목표 2개를 힌트 없이 연속 달성하면 다음 목표의 지원 감소 자격을 얻는다. 부분 이해·도움 요청은 연속성을 초기화한다. 판정 불가 입력은 독립 달성을 더하지 않고 기존 연속성을 유지한다. 정책 버전은 `SUPPORT_DECREASE_V1`이며 이 버전으로 기준 수나 초기화 규칙을 바꾸면 시작 시 거절한다.

힌트 없는 도달은 현재 목표의 승인된 필수 학습 증거가 이번 발화의 긍정 관찰에 모두 존재하고, 사전 도움·정답 제공 이력이 이를 뒷받침할 때만 인정한다. 다른 목표의 질문 지원을 복사하지 않으며 이력이 없는 과거 판정을 독립 달성으로 추정하지 않는다. 정답을 이미 제공한 목표의 응답은 독립 도달과 구분한다.

## 이번 커밋의 실행 경로

검수된 턴 → 서버의 입력 목표·관찰·사전 도움 대조 → 입력 목표 도달 방식/지원 결정과 관찰 근거 저장 → 다음 승인 문맥 조회 시 시간순 확정 이력 복원 → 정책 자격 계산 순서로 동작한다. 판정과 근거는 기존 턴·관찰과 같은 트랜잭션으로 저장하며 저장 실패 시 함께 롤백된다. 같은 요청 재전송은 기존 결과를 복원한다. 아동 삭제는 새 근거 테이블도 같은 삭제 트랜잭션에서 정리한다.

새 V30은 `roleplay_goal_assessment`의 `input_goal_outcome`·`support_decision`과 `roleplay_input_goal_basis`를 추가한다. 기존 V1~V24는 변경하지 않으며 원래 미커밋 검증본의 V26을 V30으로 옮겼다. 과거 행의 새 판정 값은 채우지 않는다. 표준 발화 삭제 후에도 검수된 학습 판정·근거는 유지해 이력을 복원한다.

원본 develop의 최대 턴 종료, 생성/검수 제한, 활동 목표 달성의 긍정 근거 검사는 유지했다. 이번 단계는 판정 저장·복원과 정책 자격 계산까지다. 생성 전 지원 수준 보정, 저장 전 보정 재검증, 한 단계 상승 제한과 판정 불가 입력의 학습 유도 횟수 제외는 다음 이관 동작이다. 자격 계산만으로 지원이 실제 감소했다고 보고하지 않는다.

## 설정과 검증

애플리케이션의 기본 설정은 목표 2개·`RESET_SEQUENCE`·`SUPPORT_DECREASE_V1`이다. 세 설정을 함께 명시해야 하며 기획 변경 시 정책 버전을 함께 변경해야 한다. 설정 없는 독립 실행에서는 임의 값을 추정하지 않고 `POLICY_REQUIRED`를 반환한다.

정책·판정·관찰 이력·승인 문맥·저장 계획·최대 턴 관련 검사와 HTTP·완료·아동 삭제 회귀 검사, `spotlessCheck` 및 마이그레이션 가드가 통과했다. 실제 PostgreSQL에서 판정/근거 저장·복원·중복 요청·롤백·삭제를 확인했다. 전체 브랜치 빌드는 지원 보정 연결 후 마무리한다. 실제 외부 모델·브라우저를 통한 종단 검증은 포함하지 않는다.
